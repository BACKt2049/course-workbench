# release-v1.0

首个包含 Windows EXE 的 GitHub Release。程序内部版本为 **1.3.1**，接续此前的 1.3.0，避免旧实例将发行包识别为降级版本。

## 下载与运行

从 [发行页面](https://github.com/BACKt2049/course-workbench/releases/tag/release-v1.0) 下载 `课程工作台-答案中心.exe`。直接双击运行，首次选择数据保存目录；已有目录仍按保存的配置读取。

EXE 内置 Python、Playwright 驱动和完整 Chromium，无需另外安装 Python、Node、Chrome 或浏览器内核。首次运行会解压内置组件；后续复用稳定目录，缺失或损坏时从 EXE 恢复。登录与同步需要网络。

天津大学使用“融合门户”App，智慧树使用“知到”App 扫码。更新程序前关闭旧窗口；保留原数据目录，不能删除它来替换 EXE。

`SHA256SUMS.txt` 用于核对下载完整性；它不等于 Windows 代码签名。本发行版没有实现程序内自动更新，使用 Release 手动下载替换。

## 本次修复

- 本地勾选状态同时保存到工作台快照与同步数据，修复“设计模式习题二已完成却再次显示未完成”。
- 同步改为增量合并，已完成任务不会因为从提醒列表消失而被删除；已关联平台 ID 的任务改名或延期仍保留原身份和本地决定。
- 任务身份包含账号、课程、任务类型和平台 ID；旧任务保留 ID 与别名，只在可唯一关联时补充平台身份，避免跨课程误合并。
- 区分本地工作状态和平台提交状态。明确的本地决定保留；平台状态未知时不推断为未提交。
- 浏览器缓存丢失后恢复本地数据；页面保存请求串行执行，减少旧请求覆盖新修改的机会。
- 修复连续课程节次未合并，以及正常考试日期中的 `-` 被当成“未安排”导致考试记录丢失。
- 二维码等待实际页面与图像就绪，移除固定等待；重复点击连接复用有效会话，取消会话后停止继续轮询。
- 桌面与命令行服务默认只监听本机，局域网访问需显式指定 `--lan`。

## 验证记录

在 Windows 11 x64 上完成：

- 79 项 Python 单元测试、36 项解析检查、8 组前端合并回归及页面脚本语法检查通过。
- 真实浏览器验证完成、撤回完成、改名、延期、刷新、清空浏览器缓存后的恢复，以及本地状态和平台提交状态同时显示；无页面 JavaScript 错误。
- 在用户数据的隔离副本中重放历史响应，验证完成状态保留、平台身份关联及改名/延期不重复；原业务文件未改动。
- 成品在独立数据目录、空浏览器缓存和不可用下载地址下运行，内置驱动及 Chromium 实际启动通过。
- EXE 原生独立窗口保持浏览器沙箱；页面、内核和驱动的临时解压资源被移开后，稳定目录仍支持页面、诊断和快照。
- 损坏配置从有效副本恢复，损坏内核从 EXE 恢复；笔记持久化和备份内容校验通过。

二维码本地回放各执行 3 次：天津大学提取阶段约从 2.6 秒降至 0.14 秒，知到约从 3.5 秒降至 0.15 秒。测试使用固定本地二维码页面，不包含真实平台网络和浏览器启动耗时，不代表已验证线上 P95 指标。

上述成品检查使用本机隔离环境，不是另一台全新 Windows 机器的验收。公开附件只包含程序、校验文件及脱敏的构建/验证信息，不包含账号、课程数据、附件、答案缓存或备份。

## 保留边界

- 尚未核实含义的平台数字状态码显示“状态未知”，不猜测完成或成绩。没有稳定平台身份且关联存在歧义的旧记录不会自动合并。
- 答案接口完整性改进继续单独排期；平台未开放答案与获取失败仍区分展示。
- SQLite 任务服务、课程工作区、Agent API/MCP、签名自动更新、学习通和微信流按开发文档后续实施。
